I want to look at how much evaluation of a skill can be done just against the generated tasklist, as this is cheaper to produce than fully generated code. For this particular skill, I recognise it won't catxh everything. Example: I can see if it chose to use openapi generator rather than writing tasks to hand code the controllers, value objects etc. But I won't be able to see if it navigated the maven build cycle correctly, including the code generation phase.

Write a simple framework that takes as input any of the kiro spec-driven task lists in the tests/tasklist-eval/samples folder, and evaluate whether the skill worked. Ignore whether the task is marked as complete or not. Some samples will have notes and execution order defined at the end, others won't, as they were generated by different versions of kiro. Support all formats. 

Use as an example evaluator the check whether all relevant tasks are using openapi-generator, but keep the specific evaluator loosely coupled from the framework.

For the first pass, we will take tasklist.md files as input, without worrying about where they come from. A separate tool could then be developed to generate task lists from the skill and curated test prompts.

Stay on the current git branch, and don't commit anything. Create the framework within the test/tasklist-eval folder, and add a README describing how to execute a sample run.

As with the skill-activation example in the test folder, allow the tool to output as text, JSON or junit XML formats, either to STDOUT or a file, for compatibility with CI/CD pipelines.
